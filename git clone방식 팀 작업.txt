팀플 git 작업 (clone)

#----- 1. 팀장이 프로젝트 생성 및 github에 프로젝트 올리기 -----#
1-1. 팀장이 팀 프로젝트를 생성
1-2. 프로젝트 파일구조 기본 생성(폴더, 패키지만 생성하고 안에 파일이 없으면 폴더가 올라가지 않으니 주의!)
1-3. remote repository 생성(레포지토리명은 프로젝트명과 동일)
1-4. git init
1-5. git branch -m main
1-6. git remote add origin 원격저장소url
1-7. git add . 
1-8. git commit -m "커밋메세지 상세히"
1-9. git push origin main
1-10. git branch dev (dev 브랜치 생성)
1-11. git switch dev (dev 브랜치로 이동)
1-12. git push origin dev (dev 브랜치도 원격저장소에 저장)
1-13. default branch를 dev로 변경(github 사이트의 settings에서 변경)
1-14. settings → Branches 규칙에서 Require a pull request before merging 체크
1-15. 공동 작업할 팀원 초대 settings → Collaborators and teams → Add people 에서 팀원 전체를 초대(권한은 Write 이상). 이게 없으면 팀원은 이 저장소에 push도, PR도 못 올립니다.

#----- 2. 팀원의 최초 작업 -----#
2-1. 팀장이 보낸 Collaborator 초대를 메일 또는 github 알림에서 수락
2-2. 팀장의 원격 저장소를 그대로 clone 
　　git clone 팀장원격저장소url
2-3. git remote -v 로 origin이 팀장 저장소로 잡혀있는지만 확인

#----- 3. 작업 순서(팀장&팀원 공통) -----#
3-1. 작업할 개인 브랜치 생성 (브랜치 생성은 dev 브랜치에서 작업)
　　git branch 브랜치명 (브랜치명은 통상적으로 개발하려는 기능에 맞게 작성한다)
　　ex> git branch feature/board-list   (새로운 기능 개 발시 주로 접두어 feature를 붙이거나, 줄여서 ft라고 쓴다)
　　　　git branch bugfix/join
　　　　git branch hotfix/reg-item
3-2. 생성한 브랜치로 이동
　　git switch 브랜치명
　　(git checkout -b 브랜치명 → 새 브랜치 생성 및 이동을 동시에 진행하는 명령어)
3-3. 코드 작업
　　코드 작업은 반드시 개인이 만든 브랜치에서 작업한다. 작업 전 반드시 확인할 것!
　　코드 작업 중 개인 브랜치가 아닌 dev 브랜치에서 작업하고 있음을 인지했으면 즉시 개인브랜치로 이동하여 add-> commit 진행한다.
       개인브랜치에 아닌 곳에서 코드 수정 -> add -> commit까지 진행했다면...어쩔수없다..
3-4. git add .
3-5. git commit -m "커밋메세지"
3-6. 작업한 내역을 원격저장소에 올림
　　git push origin 개인브랜치명
　　* commit을 했다고 해서 무조건 push 하는 건 아님!
　　* push는 해당 브랜치에서 목표했던 기능이 다 만들어지면 그때 해도 됨!
　　* 단, commit은 많이 해 놓을수록 좋음!
　　이 push는 "나의" 원격저장소가 아니라 팀장의 원격저장소에 바로 반영됨.
3-7. github 팀 저장소에서 Pull Request 생성 
         Pull Request(PR)란 push 개인브랜치의 내용을 dev 브랜치에 반영해달라는 요청을 보내는 것.
         (base: dev ← compare: 내가 push한 개인브랜치)
3-8. 리뷰어가 코드 확인 후 승인(merge)
3-9. 병합이 끝나면 PR 화면에서 'Delete branch' 버튼 클릭 (원격 브랜치만 삭제됨!)
3-10. dev 브랜치로 이동
　　git switch dev
3-11. 작업 완료한 로컬 브랜치를 삭제
　　git branch -D 삭제할브랜치명
3-12. dev 브랜치의 최신 내용 받아오기
　　git pull origin dev
